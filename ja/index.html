01 / 読む順序

一覧から探す。レポートを読む。

A 比べる情報を、近くに。

リファレンスは名前・型・値を横断して読みます。余白を詰め、行を揃えることで、読んでいる場所を見失わずに項目を比較できます。

コンポーネントの一覧を見る →

B 主張に、読む順序を。

ペーパーは主張・根拠・意味を順に読みます。型と余白に別のスケールを用いて、最も伝えたいことを前に出し、注釈をその説明対象のそばに置きます。

02 / 視覚の語彙

図1では、記号・色・揃えた段階が、図と本文の両方で同じ意味を担っています。

関係を見せることが、デザイン。

見出しが問いを示し、図が関係を見せ、キャプションが読み取るべきことを説明する。その間の余白も、説明の一部です。

文字の組み方は、読み方に従う。

密度の高いリファレンスでも、名前と値は読みやすく保ちます。密度は文字を小さくせず、余白から取ります。ペーパーでは大きな型スケールで、主張とそれを支える詳細を分けます。

印には、意味を伴わせる。

Aはドキュメント、Bはペーパーを一貫して指します。記号を添えることで、単色でも関係が残ります。状態や情報の不在には、種別の色と区別した語彙を用います。

04 / 使いはじめる

読み方を選び、内容に必要な部品を組み合わせます。

はじめに →

あなたの情報を、ページに。

文書のheadにスタイルシートを読み込み、HTMLやテンプレートにレイアウトのクラスを指定します。このページは.sheet、コンポーネントのリファレンスは.docで組んでいます。

HTML
<article class="sheet">
  <h1>明快な、読む順序。</h1>
  <p class="stand">最も伝えたいことを、最初に。</p>
  <section class="sec">
    <h2 class="label">根拠</h2>
    <div class="field">詳細は、そのあとに。</div>
  </section>
</article>
スタイルシートのURL
HTML
<link rel="stylesheet"
      href="https://k-kinzal.github.io/document-design/v1.0.0/document-design.css">
見た目を変更できますか？

型・余白・色の--dd-トークンを上書きします。カスケードレイヤーを使っているため、利用側のCSSでスタイルを変更できます。

ライトとダークで同じコンポーネントを使えます。テーマの設定を見る →

どんな操作が用意されていますか？

任意のスクリプトで、検索・並べ替え・絞り込み・タブ・コピー・テーマ切り替えを追加できます。スクリプトがなくても文書は読めます。

Search · 絞り込み · Tabs

どんな用途に向いていますか？

文章・構造化データ・コードを内容とするドキュメントやレポートに使えます。基本スタイルは文書全体に適用する設計です。既存アプリケーションに組み込む場合は、別文書として表示するか、周囲のUIへの影響を確認してください。

導入ガイドでは、対応ブラウザ、印刷、オフライン保存についても説明しています。
